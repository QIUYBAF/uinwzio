# 账号历史台账与逐期反馈归档

生效日期：2026-10-06。适用 OPS-01 及所有已经发布的 CT/IP 单集。账号历史与作品反馈是不可重建证据，归档时必须保留，不按缓存清理。

## 数据与存储

- GitHub：本制度与 PROJECT_HOME 控制入口。
- Drive OPS-01：唯一完整数据台账、原始导出/截图、历史审计证据包。
- Library / Page：最新状态摘要、台账入口、复盘结论；不另建相互竞争的完整版本链。
- 单集工程 manifest：保存 publication_key、真实发布版本、平台作品ID/URL、发布时刻、台账/证据链接与复盘状态。制作 DONE/ARCHIVE 不终止数据跟踪。
- 发布、交付、技术QA、配音/音乐许可和运营复盘分别记录；已发布或有播放数据不代表其他验收通过。

## 固定采集节奏

| 层级 | 必须保留 | 补充 |
|---|---|---|
| 账号 | 每周同一口径的粉丝存量、最近7日事件、收入、直播汇总 | 可得时导入平台每日历史序列；30日窗口另列 |
| 单集 | 发布登记、72小时、7天、30天 | 24小时可选；每月只更新仍有明显长尾的旧稿 |
| 直播 | 每场结束后或次日的有限一次记录 | 时长、观看、弹幕人数/条数、平均观看、关注、收益及实际游戏 |

发布登记后生成到期队列。每日仅检查是否有新登记或到期项目；无到期项目不进入后台全量巡检。优先 72小时，若只能在48–72小时拿到快照可作为早期参考，记录实际片龄。每日定时采集通常有约一天延迟，因此超出72小时的读数标为 late，绝不伪装精确72小时成绩。7天和30天同理。后台允许按发布时间筛选历史累计时，记录有效截止时间；页面当前总数不能当过去的窗口值。

## 记录结构

1. accounts：platform、account_id、验证方式、主页URL。
2. publications：主类＋交叉标签、系列/期数、平台作品ID、准确发布时刻与时区、真实发布文件/哈希、封面/标题版本、时长、制作成本和本期测试变化。同一期跨平台分别登记。
3. account_snapshots：observed_at/date、data_through、window_start/end、metric、value/display_value、单位、精度、scope、来源与证据。
4. episode_snapshots：publication_key、stage、target_at、observed_at/date、data_through、age_hours、lateness_hours、各指标与来源。无法确认精确时间时为 null，不补零点。
5. interventions：改标题/封面、发布时间或内容版本变更、付费推广等的时刻和范围。
6. reviews：做了什么、观察到什么、可能解释、反证与不确定性、下次只改变哪一点。
7. capture_queue：目标节点、pending/captured/late/missed/blocked 状态、失败原因、下一次有限重试时刻。
8. corrections：纠正原因与前后值。保留原始快照，不覆盖或删掉不理想的数据。

缺失数值用 null，并记录 missing/not_available/pending/not_applicable；真实0才填0。精度用 exact/rounded/estimated/unknown；保留原始显示。旧审计CSV作为原始证据保存。结构化迁移日期不是观察日期。旧数据时间冲突不擅自校正。

## 每期指标与解释

核心：播放、平均观看秒数、3秒跳出、平均播放进度、赞/币/藏/评/弹幕/分享、直接归因关注、制作时间和支出。完播、曝光、CTR、来源、观众回访只在能读到时存；封标星级和平台百分位单列，禁止当CTR，平均进度禁止当完播。录入后台截止时间；不同截止或口径的分子分母不得计算比率。

比较同平台、同阶段、相近时长与内容主类；报告样本量和中位数。播放/收藏/转粉/制作代价分别判断，不能只排播放总榜。累计数据差分只有同范围、同口径、同截止定义时才表示增量；滚动7/30日窗口的差值不是两次采集间新增。跨平台不直接混加“观看人数”。归因关注不能与账号净增、直播关注相加。

描述关联不宣称因果；每次只提出一个有证据的改进假设。成本未知不算ROI；单稿低表现不判整个系列失败。不因表现差删除作品证据。

## 归档验收

制作交付可先归档，运营复盘另标 OPEN。工程至少保留发布登记、早期48–72小时读数（目标72小时；若缺失明示missed/blocked）、7日/30日快照或明确待采任务，以及原始证据、版本变更、简短复盘链接。只有所有阶段已有数据或明确缺失原因及后续处置，复盘才标 COMPLETE。未来阶段尚未到时不得因缺失阻止成片交付。

自动任务执行不能保证登录长期有效；每次失败记录真实原因并留空，不推造数据。创建任务不等于完成采集。现有已错过节点不得用今日累计数回填。

## CHANGES

2026-10-06：用户要求持续保存账号状况，以及每一期发布后两三天与后续数据，支持折线图和可复核复盘。新增历史台账、固定节点、独立复盘状态和证据保留；不改变系列视觉身份、制作优先级或既有发布权限。
