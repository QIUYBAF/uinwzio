# Workflow — 软件开发 / 发布

1. **单一问题**：每轮只定义一个核心问题或能力增量。
2. **验收条件先行**：先写“怎样算修好/做完”，再开始编码。
3. **最小实现**：优先最小可靠方案，不先做大重构。
4. **局部验证**：单元逻辑、关键路径、错误处理。
5. **真实验证**：用实际素材/实际 Windows 环境/真实操作路径跑一遍。
6. **回归检查**：确认旧功能没有因为新功能被破坏。
7. **提交 Git**：代码和文本变更进入 GitHub；版本历史不靠平级文件夹保存。
8. **构建交付**：可运行包、EXE、模型、大资源进入 Drive 对应 `SW-*_ACTIVE`。
9. **旧版收口**：旧 Handoff / build 进入 `90_归档`，不得同时出现多个“最新版”。
10. **交接**：更新 STATUS / DONE / NEXT / BLOCKERS / FILES / CHANGES。

## 停止点
验收条件通过、真实路径可用、回归无关键问题后停止；非阻塞的新想法进入 WAITING，不顺手无限扩展。
