# Workflow — B站发布与复盘

1. **进入发布线条件**：内容项目已达到 DONE，不在发布阶段继续大改正文。
2. **最终 QA**：画面、字幕、音量、开头/结尾、署名、分辨率、帧率、导出完整性。
3. **包装**：默认准备 16:9 与 4:3 两版封面；标题准确表达核心看点，不误导。
4. **发布包**：成片 + 两版封面 + 标题 + 简介 + tags + 必要置顶评论文案。
5. **归位**：发布包进入 Drive `02_发布交付/<项目ID>/<日期或EP>`。
6. **首轮观察**：记录首日关键表现；不因短时波动连续改标题/封面。
7. **72h/7d复盘**：看点击、前段留存、平均进度、互动/收藏、播转粉、流量来源，并与账号近期基线比较。
8. **归因**：区分选题、包装、前段留存、内容质量、发布时间/流量波动，不把所有问题都归咎于作品本身。
9. **决策**：扩大 / 维持 / 改版 / 暂缓 / 停止。
10. **规则回写**：只有稳定证据支持时，才修改对应 PROJECT_HOME 的固定制作规则；否则 `CHANGES: none`。

## 停止点
每次复盘最多产生一个主要改进动作；避免因焦虑反复刷新数据或同时改多个变量。
