# Storage & Retention — 跨平台储存与保留规则

**UPDATED:** 2026-09-03  
**SCOPE:** ChatGPT Library / Google Drive / GitHub / Codex 本地

## 1. 唯一真源

| 平台 | 唯一职责 | 应长期保留 | 不应长期保留 |
|---|---|---|---|
| GitHub | ProjectOS、PROJECT_HOME、代码、文本规则、版本历史 | 源码、配置、测试、轻量文档 | 成片、工程 ZIP、模型、可执行文件、可再生成构建产物 |
| Google Drive | 大文件真源 | 原始素材、可编辑工程、母版、最终交付、程序包 | 根目录散落版本、无说明的 `final2/latest-new` |
| ChatGPT Library | AI 快速工作区 | 项目入口、短摘要、提示词、参考、少量 QA 文档 | 音视频母版、大型 ZIP、长期版本库 |
| Codex / 本地 | 执行现场 | 当前工作副本与必要缓存 | 未同步的长期唯一副本 |

## 2. 生命周期

`INBOX -> ACTIVE -> DELIVERY -> ARCHIVE`

- 不确定归属：先进入 `99_待整理`，不得凭文件名强行归项目。
- 活动项目：一个项目只保留一个无版本号的 `*_ACTIVE` 入口。
- 最终交付：保留源/母版、发布成片、封面、字幕/脚本、必要授权与 QA。
- 旧版：进入 `90_归档`，名称明确标记 `OLD`、`VARIANT` 或日期。
- 可再生成 checkpoint、缓存、重复包装、重复导出：核验后删除。

## 3. 命名

推荐格式：

`<PROJECT_ID>_<EP/模块>_<语义状态>_<可选规格>.<ext>`

示例：

- `CT-02_EP07_猪灵堡垒_FINAL_zh-CN_1080p.mp4`
- `CT-02_EP07_猪灵堡垒_SOURCE_Remotion_v2_20260901.zip`
- `CT-01_光的历史_LATER_VARIANT_1080p.mp4`

禁止使用无法判断关系的 `final2`、`new final`、`latest-new`。

## 4. 超过跨端单文件限制时

大文件仍以 Drive 为真源。若连接器单文件传输上限阻止直接上传：

1. 按不超过 90 MiB 做二进制无损分卷；
2. 同目录保存 `MANIFEST_说明与SHA256.txt`；
3. 写明重组命令、原文件字节数、原文件和各分卷 SHA-256；
4. Drive 端逐项复核大小后，才清除 Library 副本。

分卷是传输手段，不是新版本。

## 5. GitHub 防膨胀

- `.gitignore` 必须阻止视频、压缩交付包、可执行程序、模型权重、依赖和构建目录进入普通提交。
- 必需的小型测试 fixture 可在项目目录显式 `!` 解除忽略，并在 README 说明用途。
- 当前分支中的旧网页/知识分类先视为 Legacy；未经依赖审计不得大规模移动。
- Git 历史瘦身必须在本地镜像备份、标签快照和大对象清单完成后，使用 `git filter-repo` 等方式单独执行；不得在普通整理中直接 force-push。
