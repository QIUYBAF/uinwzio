# Project OS — 统一工作制度

> 目标：让 ChatGPT / Codex / 本地 / Google Drive / Library / GitHub / B站之间只传递最小必要信息，避免重复搜索、重复解释和版本混乱。

## 1. 唯一职责

- **GitHub = 控制面 + 代码真源**：项目编号、PROJECT_HOME、工作流、决策记录；软件代码与版本历史也只认 GitHub。
- **Google Drive = 大文件真源**：原始素材、PSD/Procreate 导出、音视频、模型、可执行文件、最终交付。不要在 Drive 根目录留版本堆。
- **ChatGPT Library = AI 快速工作区**：当前项目卡、短摘要、提示词、参考资料。不是大文件仓库，也不是长期版本库。
- **Codex / 本地 = 执行现场**：允许缓存和中间产物，但任何关键决定必须回写 PROJECT_HOME；本地不是长期真源。
- **B站 = 发布终点 + 数据反馈**：发布文件与数据结论回流到 OPS-01，不作为素材仓库。

## 2. 项目编号与跨端命名

所有地方都使用同一编号：
- CT-*：内容/视频系列
- IP-*：原创 IP / 世界观项目
- SW-*：软件/工具开发
- OPS-*：运营/发布/复盘
- LAB-*：研究/学习/实验

ChatGPT group、Codex 本地目录、Drive 文件夹、GitHub 项目卡都以同一编号开头。

## 3. 状态机

项目只有四种状态：`ACTIVE / WAITING / DONE / ARCHIVE`。

- ACTIVE：本周真的会推进；每周主执行项目最多 3 个。
- WAITING：保留但不主动消耗算力。
- DONE：已完成，等待发布/复盘/收尾。
- ARCHIVE：停止搜索，除非明确恢复。

任何项目不得用版本号代替 ACTIVE，例如禁止 `AgentCut_v3.2.3_ACTIVE`；活动入口固定为 `SW-01_AgentCut_ACTIVE`，版本进入 Git 历史或归档。

## 4. 项目入口文件

每个项目必须有且只有一个 `PROJECT_HOME.md`，新对话、新 Codex 会话、本地接手时先读它。内容必须控制在约 100 行以内，只记录：
1. 项目目标与观众承诺
2. 固定风格/不可破坏约束
3. 当前状态
4. 当前唯一下一交付物
5. 标准工作流
6. 完成定义（DoD）
7. 文件真源位置
8. 最新交接摘要
9. 最近一次关键决定
10. 下一步

详细历史不写进 PROJECT_HOME，只链接到日志或归档。

## 5. 标准交接协议

任何跨端交接只传 6 项：
- `STATUS` 当前状态
- `DONE` 已完成
- `NEXT` 唯一下一步
- `BLOCKERS` 阻塞
- `FILES` 真源位置
- `CHANGES` 本轮改变了什么固定规则

如果 `CHANGES = none`，下一端不得擅自重做已定型的风格与制作方式。

## 6. 文件生命周期

`INBOX -> ACTIVE -> DELIVERY -> ARCHIVE`

- 临时文件先进 `99_待整理/99_收件箱`。
- 进入项目后必须改成语义化文件名。
- 中间文件只保留能继续工作的最少集合。
- 发布后只长期保留：源文件、最终成片、封面、字幕/脚本、PROJECT_HOME、必要授权/素材说明。
- 可再生成缓存、重复导出、旧 Handoff、无意义 AI 中间图可删除或归档。

## 7. AI 默认行为

AI 接手任何已有项目时：
1. 先找项目编号和 PROJECT_HOME；
2. 不重新询问其中已有的信息；
3. 不主动重做已验证成功的风格；
4. 先完成最小可交付版本，再升级；
5. 本轮结束前更新 `STATUS/NEXT/CHANGES`；
6. 发现文件位置混乱时，优先修入口而不是大规模搬家。

## 8. 每周维护

并入 B站周决策会：
- 检查 ACTIVE 是否超过 3 个主项目；
- 每个 ACTIVE 项目是否有唯一 NEXT；
- 是否出现多个“最新版”；
- 是否有需要归档/暂停的项目；
- 若制作风格发生改变，必须明确记录为一次“规则变更”，否则保持上一期体验连续。
