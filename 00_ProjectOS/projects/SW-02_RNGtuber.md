# SW-02 RNGtuber — PROJECT_HOME

**STATUS:** ACTIVE  
**UPDATED:** 2026-09-01

## 1. 一句话目标
做一个 Windows 上真正能直接开播的轻量 RNGtuber/PNGTuber：角色自然、响应稳定、资产可维护，而不是长期停留在演示和资产修补阶段。

## 2. 项目身份 / PROJECT IDENTITY
### 核心体验
打开程序后，角色应该像一个稳定存在于桌面的二次元直播形象：呼吸、说话、眨眼、表情、服装和输入反馈自然发生，用户不需要感知复杂状态机或不断手动修错位。

### 识别特征
- **直播可用优先**：透明无边框、置顶/穿透、麦克风、快捷键、输入 Overlay、配置保存和 EXE 交付比无限增加表情更重要。
- **资产模块化但视觉必须像完整角色**：Base、眼/眉/嘴/瞳等层可独立维护，但运行时不能出现拼贴感、残影或坐标漂移。
- **统一画布 / 统一坐标**：所有可替换视觉模块共享同一坐标系；不以每个状态手工偏移作为长期方案。
- **自然低幅运动**：呼吸、轻微摇摆、voice bounce 和输入位移只提供生命感，不让人物像弹簧或镜头抖动。
- **状态切换连续**：嘴型、眨眼、表情、服装切换有合理 attack/release/淡化；环境噪声附近不能高速开闭嘴。
- **主角色与输入展示分离**：手柄/键鼠 Overlay 是独立信息层，不强行贴到人物手上破坏 master 资产。
- **可替换资产必须经过批准**：程序侧只接收已通过视觉 QA 的资产包，避免“代码修图”把错误永久化。

### 可变化区
- 状态机可以简化或扩展；表情数量、服装、输入 Overlay、动态参数都可迭代。
- 允许未来加入摄像头/追踪、弹幕、变声等，但不能阻塞核心开播链路。

### 不可无声变化
- 放弃统一坐标，重新依赖手工 offset 修脸/嘴。
- 为更多状态牺牲已有稳定眨眼/嘴型/服装切换。
- 把未经 QA 的视觉资产直接覆盖 master。
- 只在开发环境能跑、没有 Windows 可启动交付，却继续标记为“完成”。
- 大改资产协议或状态机时必须记录迁移原因和兼容影响。

## 3. 用户承诺
用户应能稳定打开程序、选择形象、开麦说话、切表情/服装并直播；角色表现自然且可预测，不需要每次开播前重新校准一堆技术细节。

## 4. 不可破坏约束
- 真透明 RGBA、统一画布与坐标是资产基础契约。
- 麦克风嘴型使用 hysteresis + hold/平滑逻辑，避免噪声抖动；阈值可配置。
- CharacterRoot 每帧从绝对状态计算，避免 transform 累积漂移。
- 表情/服装过渡使用正确 alpha 合成，不产生黑边、闪烁和位置跳变。
- master 资产替换必须通过视觉 QA 与 runtime QA。
- EXE/ZIP 构建与启动验证属于功能的一部分，不是最后可选步骤。

## 5. 当前唯一交付物
优先得到“可直接启动、视觉无明显错位、嘴型/眨眼/切换稳定”的 Windows 构建；在此前不扩展非必要新功能。

## 6. 标准工作流
1. 锁定当前 approved master 资产与坐标契约。
2. 跑资产 QA：透明度、边缘、replacement mask、关键状态对齐。
3. 跑最小 runtime：idle / talk / blink / 当前表情与服装，先验证稳定性。
4. 验证麦克风阈值、attack/release、随机眨眼和自然低幅 motion。
5. 验证快捷键、全局输入、透明窗、穿透/置顶、配置持久化。
6. Windows 构建：测试 → PyInstaller → packaged diagnostics → GUI smoke → release ZIP/SHA256。
7. 成功构建进入 Drive 唯一 ACTIVE；旧构建归档；新视觉资产只能经批准导入。

## 7. 完成定义 DoD
角色无明显错位/黑边/残影；嘴型和眨眼稳定；状态切换自然；核心快捷键与窗口功能有效；Windows EXE 可直接启动；资产与构建真源明确。
