# CT-02 结束乐队×Minecraft — PROJECT_HOME

**STATUS:** WAITING

## 1. 一句话目标
把《孤独摇滚》角色喜剧嵌进 Minecraft 生存进程，让观众同时看到“这四个人会怎么活下来”和“这个世界真的在推进”。

## 2. 项目身份 / PROJECT IDENTITY
### 核心体验
这是角色性格驱动的短篇动画喜剧，不是 Minecraft 攻略，也不是把原作人物贴到游戏背景。笑点来自角色在生存、工业、探险和战斗中的自然反应。

### 识别特征
- **角色是笑点发动机**：虹夏负责组织/推进，凉的冷淡与奇怪行为制造反差，喜多的社交/表现欲适合制造外向型包袱，波奇的焦虑和逃避适合做反转与收尾。
- **Minecraft 进度是真剧情**：装备、住房、资源、下界、堡垒、要塞等必须形成连续状态；新装备应在画面里体现工业/生存进展。
- **短而有结构**：每集围绕一个游戏目标，通常 3–5 个包袱；先建立目标，再让角色把事情搞歪，最后留一个清楚的反转/余韵。
- **动画感而非 PPT**：关键帧之间补必要的反应、动作和停顿；人物动作优先于花哨镜头效果。
- **声音是节奏的一半**：对白停顿、爆炸/快门/咀嚼/落地等音效、字幕出现时机与画面动作共同构成笑点。
- **系列比单集更重要**：上一集获得的资源、装备和经验要影响下一集，不每期重置世界状态。

### 可变化区
- 地点、游戏目标、包袱类型、BGM、单集长度和镜头风格可以按剧情变化。
- 某些重剧情段可拆成两期，不强求一集塞完完整游戏章节。

### 不可无声变化
- 角色性格为迁就梗而失真。
- Minecraft 进度突然重置或装备/资源无解释消失。
- 从动画式反应变回只有推拉/抖动的静态 PPT。
- 为“更炫”加入大量转场/特效，盖住对白与包袱。
- 改变系列节奏规则时必须写 `CHANGES`。

## 3. 观众承诺
观众应能追着角色关系和 Minecraft 世界状态看下去：每集既有独立笑点，也能感觉她们真的从第一晚一路发展到了下一阶段。

## 4. 不可破坏约束
- 角色视觉辨识和性格优先于梗密度。
- 游戏目标必须真实推动剧情，不能只是背景皮肤。
- 对白节奏优先于特效；BGM 不压台词与关键音效。
- 关键动作要有必要运动/反应帧，不能仅靠镜头推拉伪装动画。
- 同类笑点不要机械重复，优先用游戏新状态制造新冲突。

## 6. 标准工作流
1. 先写本集唯一 Minecraft 目标与开场状态（装备/资源/地点）。
2. 围绕目标设计 3–5 个角色包袱，避免脱离游戏进度硬插梗。
3. 写完整分镜/对白，标出反应帧、停顿、音效点和结尾反转。
4. 生成/绘制关键画面并补必要动作帧。
5. 剪辑顺序：对白节奏 → 动作/反应 → 音效 → 字幕 → 转场/特效 → BGM。
6. QA：笑点是否成立、剧情是否推进、角色是否一致、前段是否拖、装备/世界状态是否连续。
7. 发布后只用真实留存/互动反馈调整下一集，不因一集表现推倒系列。

## 7. 完成定义 DoD
故事闭环；至少一个明确游戏进展；主要包袱无需解释即可理解；声音/字幕平衡；成片与封面完成；世界状态已回写。
